# ДЗ 5

Лише стандартна бібліотека Python.

## Запуск

```bash
python task_1.py
```

Тексти `article_1.txt` і `article_2.txt` у кодуванні cp1251. Для кожної пари (текст, підрядок) спочатку перевіряється, що алгоритм повертає той самий індекс, що й `str.find`. Потім час міряється через `timeit` (середнє за 20 запусків, секунди).

## Алгоритми

- Боєр-Мур: порівняння з кінця підрядка, зсув за правилом поганого символу.
- Кнут-Морріс-Пратт: префікс-функція, текст проходиться один раз без повернень.
- Рабін-Карп: рухомий хеш вікна, повне порівняння лише при збігу хешів.

Кожна функція повертає індекс першого входження або `-1`.

## Підрядки

- Існуючий у обох текстах: фраза з середини статті.
- Вигаданий: `квантовий алгоритм сортування бананів` (у текстах його немає).

Точні числа залежать від машини і щоразу трохи відрізняються. Порядок алгоритмів стабільний.

## Висновки

- Стаття 1: найшвидший Боєр-Мур, далі КМП, найповільніший Рабін-Карп.
- Стаття 2: той самий порядок, найшвидший Боєр-Мур.
- В цілому найшвидший Боєр-Мур: приблизно в 6 разів швидший за КМП і в 20 разів швидший за Рабіна-Карпа.
- Для вигаданого підрядка всі алгоритми повільніші, ніж для існуючого, бо мусять пройти весь текст. Існуючий підрядок знаходиться приблизно на середині тексту.
- Боєр-Мур виграє тому, що на довгому підрядку і великому алфавіті (кирилиця) він часто пропускає багато символів за один зсув.
- КМП проходить кожен символ тексту один раз, тому стабільний, але не пропускає символи.
- Рабін-Карп найповільніший, бо на кожній позиції рахує хеш з множенням і діленням за модулем. У Python це дорожче за прості порівняння символів.
- Усі три алгоритми написані на чистому Python. Вбудований `str.find` працює на C і у цьому порівнянні не бере участі.
